# Operational configuration

The verified local fallback uses PostgreSQL and private durable filesystem objects. Production uses PostgreSQL and private S3-compatible storage. The fallback is development-only; a loopback-only `LOCAL_PRODUCTION_TEST=true` opt-in allows testing a production build locally. It does not establish production readiness.

Production runtime: Node 24, HTTPS, a canonical `APP_BASE_URL`, independent random `AUTH_SECRET`, `TRACKING_HMAC_KEY` and 32-byte hex `TRACKING_ENCRYPTION_KEY`, database pooling, and `STORAGE_ADAPTER=s3`. Remove `SEED_PASSWORD` and local database/storage credentials. Run `npm run db:deploy` as a release step before starting the app. Never run a destructive schema reset. Provision the initial admin using `ADMIN_BOOTSTRAP_EMAIL` and `ADMIN_BOOTSTRAP_PASSWORD` with `npm run admin:bootstrap`; supply them privately and remove them afterward. Bootstrap refuses to overwrite an account. Rider resets are performed by an authenticated admin.

Create a private bucket using `npm run storage:init` on local MinIO. The app's storage identity needs only put/get/delete on the configured private bucket. Bucket creation/policy administration should use a separate deployment identity in production. Block public access at the provider; do not grant public object ACLs. Uploads pass through the authorized app, so no browser bucket CORS rule is needed. Streamed proof responses are `private, no-store` and require current access on every request.

Configure the reverse proxy/runtime to accept multipart bodies up to 11 MiB and apply appropriate request timeouts. The app bounds the actual stream to 11 MiB and each photo to 10 MiB, decodes at most 40 million pixels, strips metadata and stores a re-encoded JPEG. Verify that the chosen host supports this request size. Filesystem fallback objects must remain outside `public`, under a directory writable only by the app identity; set Windows ACLs or POSIX permissions accordingly. Do not serve that directory directly.

Use `/api/health` for liveness and `/api/ready` for database/storage readiness; neither returns configuration. Set `TRUST_PROXY=true` only when a trusted reverse proxy overwrites `X-Forwarded-For` and direct app access is blocked. Rate limits are PostgreSQL-backed across instances. Without trusted proxy information, the local bucket is shared across callers.

In-app notifications commit with the domain mutation. Per owner instruction, tracking uses parcel codes and needs no SMS; parcel creation never queues SMS. Existing outbox tools are retained only for historical events or isolated local simulation. The worker uses `SKIP LOCKED`, five-minute leases, at most five attempts and bounded exponential retry. A simulated SENT event explicitly says no real SMS was sent. `npm run outbox:retry -- <event-id>` queues a FAILED historical event again without sending it. No real provider is configured or enabled. Exactly-once external delivery would require provider idempotency if a future owner-authorized integration is added.

Schedule `npm run photos:cleanup` hourly. It claims only unattached STAGED/DELETE_PENDING assets older than 24 hours before deleting objects. It never removes attached proof or delivery attempts. Delivery attempts are append-only in PostgreSQL. Request idempotency records have a minimum replay horizon of 24 hours and are currently retained beyond their `expiresAt`; no automatic operational-data retention/deletion policy is implemented.

Back up PostgreSQL with encrypted `pg_dump` archives and back up all private objects and the tracking encryption/HMAC keys separately, with restricted custody. A database-only restore is incomplete. Rehearse restoration into an isolated environment: restore DB, objects and matching keys; run readiness, log in, redisplay a tracking code, open a historical proof and check assignment ownership. Record the rehearsal before release. Key rotation requires a version-aware decrypt/re-encrypt migration; do not replace the key blindly. Confirm retention/deletion periods with the owner before deleting recipient data or attached historical evidence.

Outstanding production validation: MinIO/S3 integration in an environment with reachable infrastructure, deployed HTTPS/cookies/proxy limits, backup/restore rehearsal and shared infrastructure sizing. SMS is not needed. The owner revised the local benchmark to 100 synthetic parcels with 20 concurrent readers; see ACCEPTANCE.md for measurements. Larger production capacity remains unverified.
